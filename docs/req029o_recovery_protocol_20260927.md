# REQ029O — prospective source-only recovery protocol specification

Scope: implement and test a distinct protocol; no inference, new task release, Docker execution or live poller is authorized here. Preserve the frozen comparator implementation and old approvals. A new release must select this protocol explicitly and pin every changed source.

1. Validate response envelope, exact native input binding, expiry, source/config pins, one choice, integer usage and total-token equality BEFORE classifying formatting. Transport, ownership, resource, length, malformed response, usage and provenance failures remain terminal. Only a complete stop response with zero or multiple command fences receives format feedback. Empty single commands remain terminal as a declared stricter safety/semantic gate, not claimed upstream equivalence.
2. Retain exact raw response durably before interpretation. The worker must publish a valid envelope even when formatting fails. No action claim or sandbox dispatch follows an ambiguous command response.
3. The controller publishes a distinct hash-bound format-feedback envelope referencing the exact response/object, sequence, request and protocol. Its user message is the pinned upstream text: `Please always provide EXACTLY ONE action in triple backticks, found N actions.` N is recomputed, not trusted from a peer. No additional explanatory prompt or hidden feedback.
4. Both roles append ONLY that user message to model-visible history on a format failure; the invalid assistant response remains in immutable raw/metadata evidence. On a clean command/observation append the usual assistant/user pair. Both branches update the same response/observation parent hashes and advance physical generation sequence once. Conflicting feedback/history is terminal.
5. Count every generation, including format failures, against the same24-call budget and single1800-second phase including relay/toolwait. No same-sequence regeneration, reload, deadline renewal or transport retry. An error followed by a new budgeted generation is agent continuation, not a retry of the earlier request. Durable model claims precede dispatch; action claims occur only for an accepted command.
6. Three consecutive format errors terminate; a clean completed action resets the count. Both roles independently derive this state from the chain. Final error evidence and cleanup must persist even if publication fails. Publication after cleanup uses the separately qualified bounded reporting reserve, never renewed execution permission.
7. Required integration fixtures: error→action with exact next prompt; three errors→terminal; two errors→clean→two errors; cap24 including errors; expired deadline after feedback; mutated count/body/parent/raw/native/usage rejects; crash after model claim never redispatches; feedback publication conflict; independent cleanup on either role's death. Execute actual worker/controller and transport fixtures, not merely a parser-state simulation.

Scientific release remains separate. Use fresh development tasks from a prospectively frozen rule, retain prior Qwen/Django and Astropy outcomes unchanged, and do not choose tasks or change budgets to secure positive results. Resource feasibility for both comparator arms is a separate gate. Success of protocol tests is not evidence of coding competence or routing benefit.

Readiness55%,Δ0,range45–65%; competent fixed-target comparisons/valid inference, manuscript synthesis, independent reproducibility and author-approved package remain.

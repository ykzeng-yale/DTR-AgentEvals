## Lead conclusion

The route remains worth testing because sequential feedback can, under explicit conditions, change which continuation is valuable, while randomized logging can support evaluation of several frozen regimes. Neither property implies that our present benchmark has exploitable feedback or that offline evaluation is cheaper at useful precision. The existing fixed learned schedule and unresolved calibration results are reasons to sharpen the experiment, not evidence for universal failure or success.

Our next contribution should be an auditable evaluation design for **a fixed agent harness with changing model choice**, including informative negative controls and a fair test of history dependence. Standard DR/OPE, generic SMART logic and familiar allocation ideas are prior methods. Claims of novelty and practical benefit must be narrower than simply applying these names to agents.

## How the review changes the design

| Problem in the current evidence | Decision | What would discriminate explanations |
|---|---|---|
| Learned LSL is a fixed schedule | Compare a feedback router with a prompt-only router under the same initial action/class, and with all competent fixed schedules | Variable history-dependent actions plus a held-out gain would support adaptation; collapse or no gain would limit the claim |
| Weak visible checks and few late opportunities | Use persistent repository/tool feedback; qualify outcome tests and measure prospective second-decision occupancy | Adequate observations with no effect differs from an uninformative harness; retain both outcomes |
| Favorable means with uncertain calibration | Separate value accuracy, selection regret and fresh improvement; validate the complete sampling/analysis procedure | Exact-truth coverage/type-I diagnostics and fresh-reference uncertainty can expose inference defects |
| Different methods buy different data/compute | Account for logging, fitting, profiling, retries and final evaluation; compare one-policy and catalog evaluation | A gain after the full resource ledger supports efficiency; a shared-log advantage that vanishes for one policy has a narrower use case |
| A new conditional SE appears to settle the branch discrepancy | Retain the primary expected-total target; label conditional-frame results secondary | Source/selection/recovery evidence and matching repeated-study validation, not a target switch |

## OPE precedents: what transfers and what does not

**COBS and SOPE.** COBS varies horizon, stochasticity, reward sparsity, policy mismatch and state representation. Its paper uses Monte Carlo on-policy reference values; the pinned Graph helper named `calculate_exact_value_of_policy` actually samples 5,000 episodes, while the separate experiment runner uses at least 10,000. SOPE's Graph code uses nested sample sizes from a common trial and explicit action probabilities. Adopt controlled generator factors and paired method comparisons; require our own exact finite-history truth and full-study coverage experiment. Nested sizes are not independent repetitions. Neither inspected tree exposed a license grant, so their code is reference-only pending permission. [COBS methods/Appendix F](https://arxiv.org/html/1911.06854v3), [SOPE §§5–6](https://proceedings.neurips.cc/paper/2021/file/9dd16e049becf4d5087c90a83fea403b-Paper.pdf), [pinned Graph helper](https://github.com/clvoloshin/COBS/blob/bc76441438c5a336b05cfddbf9e7242c862e64ea/ope/envs/graph.py#L170-L204).

**SCOPE-RL.** Its separation of logging, offline learning, OPE and policy selection is useful. We can reuse compatible estimator interfaces after independent equality checks. Do not adopt its confidence helpers unchanged: at the inspected revision, the Hoeffding width multiplies by n inside the square root and uses an observed maximum; the symmetric t interval uses the 1−alpha quantile rather than 1−alpha/2. Its scalar bootstrap also lacks our task/source/branch design. Two reviewers inspected the first two formulas independently; this is a static defect finding, not a measured coverage claim or a verdict on every package estimator. [Paper §§3–5 and confidence appendix](https://arxiv.org/pdf/2311.18206), [pinned code lines 505–631](https://github.com/hakuhodo-technologies/scope-rl/blob/b1c9e9fbfddd924362160ec5e9f9f071abc7b7ea/scope_rl/utils.py#L505-L631).

**Open Bandit Pipeline.** Its randomized logs, recorded action probabilities and separate on-policy references are relevant. But the reference is estimated, and its one-decision setting cannot validate sequential occupancy or selected-prefix inference. Its synthetic reward helper averages known conditional means over supplied contexts: exact for that conditional target, not every population. We will borrow the contract and one-stage control, not its bootstrap as our fixed-task CI. [Paper §§5.1–5.2 and Appendix C](https://arxiv.org/pdf/2008.07146), [pinned example](https://github.com/st-tech/zr-obp/blob/8cbd5fa4558b7ad2ba4781546d6604e4cc3e07c4/examples/obd/evaluate_off_policy_estimators.py#L131-L169).

**DOPE and RL Unplugged.** Separate absolute value error, ranking and selected-policy regret; retain frozen policy IDs and separate tuning from final assessment. DOPE uses estimated on-policy references. Its inspected plotting notebook bootstraps candidate-policy indices for benchmark summaries, which is not task-block sampling or a policy-value CI experiment. The example wrapper also clones an unpinned external implementation, so a wrapper SHA alone is insufficient reproducibility. Adopt catalog/version discipline and untouched evaluation; avoid importing large environments merely to add benchmark names. [DOPE §§2–3.2](https://arxiv.org/pdf/2103.16596), [RL Unplugged §§2.2,4](https://proceedings.neurips.cc/paper_files/paper/2020/file/51200d29d1fc15f5a71c1dab4bb54f7c-Paper.pdf), [pinned DOPE notebook](https://github.com/google-research/deep_ope/blob/7851b0e1f71dc03290428b1a76cc79f8fed1e749/plots.ipynb).

**Established estimator/design anchors.** Jiang–Li separate policy learning, nuisance fitting and evaluation and tie concentration to independent trajectories and bounded scores. Li et al. optimize allocation for contrasts between fixed global policies; an allocation efficient for that contrast may not explore switching histories. Their assumptions and design classes do not establish optimality of our branch sampler. The inspected allocation code uses sampled references and lacks a visible root license; use the mathematics with attribution, not unlicensed source or an inherited optimality claim. [Jiang–Li §§4.3,6](https://proceedings.mlr.press/v48/jiang16.pdf), [Li et al. §§2–4](https://proceedings.neurips.cc/paper_files/paper/2023/file/98d0ad88db1e51bd0aa341a823290ece-Paper-Conference.pdf), [allocation implementation](https://github.com/tingstat/MDP_design/blob/7af5c20bce4810bf6be3e8808bdccafe9657b679/NTMDP_simu.py).

## Simulation and sequential-trial lessons

**ADEMP.** Morris, White and Crowther organize simulation around aims, generating mechanisms, estimands, methods and performance measures. Their §§3–5 emphasize explicit failure handling, paired methods and Monte Carlo uncertainty, including choosing simulation repetitions for precision. We adopt that structure: exact targets, deliberately favorable/unfavorable cells, fully specified independent study repetitions and MCSEs. A large n per simulated study cannot replace enough independent repetitions, and simulation repetitions cannot replace enough real task/execution units. [Full primary text](https://arxiv.org/html/1712.03198v3), [final article DOI](https://doi.org/10.1002/sim.8086).

**Micro-randomized trials.** Cohn, Qian and Murphy's binary-outcome sample-size study shows why treatment availability and outcome/effect assumptions belong in planning. Its proximal excursion-effect target and scheduled randomization assumptions differ from our terminal-policy value and adaptive stopping. We should measure prospective decision availability and simulate our actual test, not plug the number of tool calls into its sample-size calculator. A longer nominal horizon with little eligible occupancy buys little information about later routing. [Author-hosted full paper](https://escholarship.org/content/qt61903425/qt61903425.pdf), [published article](https://doi.org/10.1002/sim.9748).

**SMART engagement simulations.** Basu's staged intervention design motivates rerandomization after observed response. However, the inspected official main R script does not provide a trustworthy off-the-shelf power comparison: each A/B endpoint can be detected in only one of three disjoint simulated populations per repetition, while its count is divided by 3B; the SMART count is divided by B. Thus that A/B endpoint-power calculation is capped at 1/3 when runs complete. This was independently checked from source, without executing R, and does not reproduce or invalidate every published result. We require identical declared detection events/eligible denominators and resource matching when comparing designs. [Paper methods](https://www.nature.com/articles/s41746-024-01330-2), [official code, lines 144–205](https://github.com/sanjaybasu/smart-engagement/blob/d30db2b921df9969976da9a72a18294e0a04ab33/Smart%20Engagement.R#L144-L205).

## Reuse and resources: selected path

Use mini-swe-agent's maintained execution loop and SWE-bench's test evaluator, with a narrow model-choice/probability ledger adapter. Use the pinned RouteLLM local classifier for a clearly labeled transferred static baseline. Keep BrowserGym/AgentLab as a secondary mechanism option. SCOPE-RL/OBP offer reference interfaces and cross-checkable estimators; our fixed-task sampling layer and uncertainty analysis require explicit implementation and review. COBS/SOPE/MDP_design stay source-reference-only until licensing is resolved. BAAR's author code was not verified as released. Router-R1's coordinator/RL stack is a different and costlier intervention.

No API key is required for this research or for the proposed local baseline in principle. Future local experiments need an existing worker that can host the chosen model pair and a disposable container environment; model fit, image architecture, context limits, throughput and storage remain unmeasured. Code licenses do not substitute for model/dataset/task-repository terms. No paid service, model download, installation or experiment has been started. Resource details can be supplied later; the protocol does not assume a particular GPU.

# REQ030AG v7 RTX PRO 6000 Blackwell route — 30 September 2026

## Decision

V6 was staged but never submitted. Its B200 and H100 `sbatch --test-only`
estimates both forecast preemption of running scavenge work on the candidate
nodes. The lead rejected those routes to avoid interrupting unrelated jobs.
The selected `gpu_rtx6000` route requests one NVIDIA RTX PRO 6000 Blackwell,
8 CPUs, 128 GiB and the same 36-hour standard allocation. Same-shape estimates
under both authorized accounts projected the same node and start time,
2026-09-30 08:39:35 ET, with no `Preempts` entry. `pi_gt353` keeps the run with
the already staged project artifacts; this does not use account switching to
evade limits. No peer job was interrupted.

The three inspected Macs cannot provide the frozen CUDA model pair treatment:
the mini has 16 GiB unified memory, the two laptops have 32 GiB each, and the
models' combined BF16 weights are approximately 44 GB. The laptops also showed
heavy swap use and 96–98% local disk use. Local Apple GPU execution would change
the pinned CUDA treatment. RTX PRO 6000 Blackwell provides 96 GB device memory
and is the smallest currently schedulable standard GPU candidate observed with
no predicted peer preemption.

## Frozen cohort and changed treatment

V7 retains the exact eight pre-outcome issue IDs from eight repository
families, public prompts, evaluator/control bytes, SIF pins, 7B/14B model
revisions, BF16 dtype, PyTorch 2.9.1, Transformers 4.51.3, CUDA 12.8, prompt,
decoding, action budget, 16 model episodes, paired order, endpoint, uncertainty
rules and controls-first gate. It reuses the eight SIFs acquired by v5 job
`27928205` and verifies every image's SHA-256 and byte size before inspection.
The v6 source-state correction remains: accept only the declared clean base or
the exact single-parent `SWE-bench` setup child, then grade against that exact
initial image HEAD while harvesting the candidate patch against `base_commit`.

V7 changes the GPU treatment prospectively from B200 to NVIDIA RTX PRO 6000
Blackwell. This is not claimed to be numerically or kernel-equivalent to B200,
H100, or the historical Metal/GGUF treatment. Both model arms use the same
frozen RTX device and runtime within this development screen. The runtime gate
checks the exact GPU model before image controls and model-asset download; the
post-load gate requires at least 20 GiB free after both weights are resident.
Any image, baseline, reference, runtime or capacity failure remains an
infrastructure/unknown outcome, never a model zero. All eight baseline and
reference controls must pass before weights are downloaded or episodes begin.

This remains a purposive eight-family DEVELOPMENT feasibility screen. It is
not a population estimate, router contrast, fixed-target MBPP/HumanEval
validation, full benchmark, or CONFIRM. A positive pair-feasibility result
permits a separate lead review; it does not release another model cohort.

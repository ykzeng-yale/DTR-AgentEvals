# REQ030T — pinned mini-swe-agent execution-path audit

**Decision:** the Seaborn strict evaluator control is valid for one task, but the actual agent-to-model execution path is not yet integrated or qualified. Current lead bottleneck is harness/model-interface design and a missing competent comparison—not Bouchet GPU capacity, and not a demonstrated failure of the DTR theory.

## Scientific question and evidence boundary

The immediate question is whether the accepted evaluator can be connected to a common, source-pinned agent loop whose task prompt, model rendering, action parser, sandbox observation, and terminal submission are all recorded before any model outcome is observed. REQ030R answers only the evaluator-control part: one frozen Seaborn issue has two expected baseline failures and all 250 declared checks pass under its reference patch. It supplies no agent behavior, model competence, routing opportunity, or independent-task variance. The check IDs are nested within one issue and must not be used as the sample size.

## Source-derived contract and implementation gaps

1. `default.yaml` fixes one system message requiring exactly one `mswea_bash_command` block and a THOUGHT section. Its task template injects the public task and the explicit terminal command `echo COMPLETE_TASK_AND_SUBMIT_FINAL_OUTPUT`, which must not be combined with another command. These prompt bytes are part of the treatment and must be frozen, not rewritten to make a candidate more likely to pass.
2. `actions_text.py` accepts exactly one regex-matched action; zero or multiple actions raise `FormatError`. `DefaultAgent` sends the accumulated message history to `model.query`, executes parsed actions through `env.execute`, and appends the formatted observation. Its defaults `step_limit=0` and `wall_time_limit_seconds=0` mean unbounded; a study runner must set finite limits explicitly. The default format-error recovery is up to three consecutive errors, so it also affects call budget and must be held constant.
3. The upstream model protocol is duck-typed (`query`, `format_message`, `format_observation_messages`, `get_template_vars`, `serialize`). The existing LiteLLM text adapter is API-backed; the REQ030C Qwen deployment script instead performs two direct tokenizer/model generation probes. Therefore neither is the missing native-HF mini-swe adapter. Native chat-template rendering, `input_ids`, output IDs, finish reason, and token counts need to be emitted by the actual adapter for every physical request.
4. The pinned default Docker environment is not suitable for this study: its subprocess and cleanup path controls Docker containers, whereas the accepted Bouchet execution boundary is Apptainer with a separately owned, bounded supervisor and guardian. Reusing the prompt/parser does not qualify the environment implementation.
5. The public task file and evaluator-only reference diff/250-ID manifest are separate inputs. Only the public projection may enter the agent prompt/history. The evaluator must consume the submitted patch after the trajectory is sealed; it must never be imported, mounted, or serialized into a model-visible message. The adapter below strips message metadata and rejects non-text/tool roles, but it cannot distinguish a secret pasted into ordinary user text. A runner that constructs model history exclusively from the public projection and sandbox observations is still required to enforce this boundary.

## Scientific diagnosis and next gate

**Design:** REQ030R's two-arm control is correctly paired at the task level and validates the strict endpoint, but `n=1` cannot estimate a task-population success rate or a routing contrast. **Implementation:** prompt/parser and supervisor components exist, but there is no qualified native-HF model adapter joined to the real mini-swe loop and Apptainer tool boundary. **Measurement:** deployment probe token bindings and control receipts are individually useful, but no model task trajectory has been captured under this joined path. **Inference:** even a successful Seaborn repair would be a single development observation, not evidence for history-aware routing; 250 test statuses do not create 250 independent units. **Capacity:** the B200 deployment probes show enough memory for Qwen2.5-Coder-32B BF16 in a one-GPU allocation, so capacity is not the current gate for that candidate. They say nothing about task competence or whether a smaller comparator is competent.

The current theory is not falsified by these results. The immediate scientific limitation is the absence of a *competent, common-harness executor comparison* on independently sampled eligible issues, followed by the missing task/family-level precision and inference contract. A positive single-task outcome would not close those gaps. As a concrete source-only advance, `experiments/lead_req030/native_hf_text_adapter.py` now implements the pinned mini-swe `Model` protocol around an injected HF tokenizer/model and the actual upstream text parser. Seven inert adapter tests exercise native render-then-tokenize bindings, exact one-action parsing, malformed output retention, observation formatting, context rejection before generation, strict decoding arguments, request/response/error callbacks, and a one-action terminal submission through the pinned `DefaultAgent` source. The pinned agent test uses a minimal Pydantic/package-startup stub because those dependencies are not installed in the local test venv; it is not a full installed-package or real-environment run. Three additional public-input tests bind `mwaskom__seaborn-3187` to the exact public-projection SHA, reject schema/hash changes, and confirm that only the public problem statement is placed in the test agent prompt. Together with the prior parser/supervisor tests, the focused suite passes 15 tests. The adapter contains no weight loader, evaluator or sandbox launcher; it is not production-integrated. The demonstrated public-input boundary remains a required runner test, not a claim established by role validation alone. Then a lead-reviewed source/config freeze can name the candidate models, task frame, estimand, assignment opportunities, and independent unit. No task inference is authorized by this audit or by REQ030R.

The commit identity above was checked by comparing the five local file hashes with the raw files at the exact upstream commit. This is source inspection, not a test execution against Qwen, the Apptainer image, or a live task. No model was loaded and no generated command was run.

## Parallel execution without outcome-driven retries

After the whole gate passes, the coordinator publishes a new immutable AJ-
compatible admission manifest for fresh AI workers. Its one-GPU field describes
one cell worker; the actual allocation GPU count remains in the AL outer
release and summary. Each subprocess receives one assigned Slurm GPU through
`CUDA_VISIBLE_DEVICES`; two workers never share an assigned GPU. A shared
weights cache avoids independent downloads/copies per cell. Every cell starts
with a fresh source workspace and model process. No cell is retried.

The execution queue prioritizes the prospectively fixed Latin-position waves
across all eight families. It retains the existing 24-call, 1,536-output-token,
16,384-context limits, deterministic decoding, decision calls 1/9 and complete

when that envelope fits both the allocation's monotonic budget and the

`NOT_ATTEMPTED`, unknown and in their assigned denominators. They cannot be
replaced with an outcome-selected passing subset.

The independently bounded whole-allocation guardian counts the owned run,
including model cache and results. Its cleanup checks include started control,
asset and GPU-runtime work even when no model cell starts. Each AI owner-pipe
guardian still handles caller death, model/load/call/episode bounds and tool
cleanup. Running cell receipts are copied into the aggregate so a grading
process cannot disappear from cleanup accounting. Any unverified cleanup holds
future dispatch. Private cell stdout/stderr is retained under a 4-MiB cap.

Candidate grading requires an eligible explicit submission, exact patch and
invocation bindings, fresh isolated evaluator workspace, complete stage
receipts and the same prepatch installed runtime as accepted controls. Strict
required-status and upstream-semantic reports remain separate. Missing test
